## What was broken and why

### Bug 1: "Video.Unsupported Desktop" + videos playing stretched on iPhone
**Root cause**: Ash's event clips are iPhone HEVC (H.265). Old code only compressed videos >45MB.
Small HEVC clips (brunch clips ~30-40MB) bypassed compression entirely → sent to Telegram as-is.
Telegram Web Desktop cannot decode H.265 → "Video.Unsupported Desktop".
Portrait iPhone videos have rotation metadata tag. When posted as-is, some players don't apply it → stretched.

**Fix in `src/lib/videoCompressor.ts`**:
- ALL videos now go through libx264 transcode (not just >45MB)
- `-movflags +faststart` added — required for Telegram Web streaming
- NO `-map_metadata -1` — rotation metadata preserved, players apply it correctly
- Large videos (>45MB) still get bitrate cap (`-maxrate 2500k -bufsize 5000k`)

### Bug 2: 0 captions on all posts
**Root cause**: `captions` table had a CHECK constraint that didn't include `telegram_test`.
Every caption upsert for telegram_test silently failed with a constraint violation.
Captions were generated by the edge function but never saved to DB.

**Fix**: DB migration applied:
```sql
ALTER TABLE captions DROP CONSTRAINT captions_platform_check;
ALTER TABLE captions ADD CONSTRAINT captions_platform_check
  CHECK (platform = ANY (ARRAY['x','telegram_free','telegram_free_vip','telegram_vip','telegram_test','website']));
```

### Bug 3: Multiple videos in one batch — only some posted
**Root cause**: `postScheduledItems` used `Promise.allSettled` — all items processed concurrently.
ffmpeg.wasm is a singleton. Concurrent `exec()` calls corrupt its state → silent failures.

**Fix in `src/lib/telegramPoster.ts`**:
Changed from `Promise.allSettled(items.map(...))` to sequential `for...of` loop.

## Current videoCompressor.ts pipeline (the correct state)
```
ALL videos → ffmpeg.wasm:
  -vf scale=trunc(iw/2)*2:trunc(ih/2)*2
  -c:v libx264
  -preset ultrafast
  -crf 28
  [if >45MB: -maxrate 2500k -bufsize 5000k]
  -c:a aac -ar 44100 -ac 2 -b:a 128k
  -movflags +faststart
  -y output.mp4

NO -map_metadata flag (rotation preserved by default)
```

## DO NOT change these things without understanding them
1. `-map_metadata -1` was a mistake that caused stretching. Do NOT add it back.
2. The size check for compression was removed deliberately. ALL videos must compress.
3. `postScheduledItems` must stay sequential. Concurrent ffmpeg = corrupted state.
4. `captions` CHECK constraint now includes `telegram_test` — don't remove it.
